B. Partial overlap
------------------
On shared samples S_nm = S_n ∩ S_m, the first-order term in log r_nm is a_n^{(nm)} - a_m^{(nm)}, with a_n^{(nm)} = ⟨u_n, ψ⟩_{S_nm} / ‖ψ‖_{S_nm}². This is a coboundary of a single node potential iff a_n^{(nm)} does not depend on the neighbour m, which holds when every neighbour pair sees the same samples (ρ=1). For a sliding window, S_nm is a different subset for each edge, so the 1-cochain generally has a nonzero curl around plaquettes.

WHAT THIS DOES NOT SHOW
=======================
- This is a classical numerical simulation of complex arrays. Using i and a Hilbert-space notation for a veil does not make the simulation quantum, and it does not demonstrate entanglement, a quantum advantage, or a new physical chip.
- There is no CMOS, timing-error, voltage, or energy model here. The notebook does not compare a tile array to Razor-style detection or adaptive voltage scaling. That measured-result claim still needs an FPGA or ASIC experiment.
- The two-term error law is a leading-term calculation with approximate constants. A fitted c_floor or c_layout far from 1 is a limitation of that calculation, not a licence to treat the fitted numbers as a theorem. N* extracted from a finite N grid has interpolation error, and a 'no crossing' result is only a bound.
- Partial overlap on the expander is not a sliding window (an expander has no geometry). Ring and torus use exact windows that guarantee ρK shared samples on every edge. If the expander construction failed to reach the target overlap, that is stated in the window-info lines above, and those points should be read with care.
- A programming model in which the programmer declares Ξ_crit(c) is not implemented here.
